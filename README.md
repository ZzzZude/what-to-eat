# 今天吃啥

面向日本生活场景的手机网页应用。当前已完成多人组队选择食物，以及通过当前位置或手动指定地点、设置范围、查找附近餐馆、随机选择和打开地图路线的核心流程。

## 已完成

- 输入昵称，创建房间或通过六位房间号加入。
- 房间成员共享候选食物清单，页面约每 3 秒读取一次更新。
- 成员可以添加候选、删除自己提交的候选；房主可以删除任意候选、清空清单。
- 房主从云端候选中随机抽选，所有成员读取同一份结果，刷新后仍可查看。
- 添加、删除或清空候选后，旧抽选结果失效。
- 抽选历史保存在数据库，目前没有历史列表页面。
- “附近吃”支持浏览器定位，以及 500 米、1 公里、2 公里的范围选择。
- 定位与手动指定两种方式可切换。手动输入日本车站、地址或地点，检索后从候选中确认搜索中心，再查找餐馆，不需要设备定位权限。
- 地点候选可以先在地图确认。同名地点由使用者选择；车站检索不会自动使用相近行政区作为车站。更改输入、搜索中心或位置方式会清除旧列表与抽选，过期的定位回调也不会覆盖手选地点。
- 页面不展示经纬度或定位精度，搜索中心只展示地点名称。同名候选使用“候选位置”编号区分，并提供地图确认入口；坐标继续用于搜索、距离和导航。
- 手选地点后自动收起输入和候选列表，点击“更换地点”可以再次展开，也可以保留当前地点后收起。仅展开、收起不会清空已有餐馆或抽选；实际更改输入或选择其他地点才会清除。
- 通过 Hot Pepper 搜索收录餐馆，展示店名、类型、地址、估算直线距离及店铺详情链接。首次展示符合条件的较近餐馆，列表最多 20 家；匹配总数与当前显示数量分别展示。
- “显示家数”放在餐馆列表顶部，与整批替换一起使用，可选 5、10、15、20 家，默认 20 家。减少时保留前面的店铺，将暂时收起的店铺留作后续候选；增加时先补回候选，不足时继续按同一搜索条件读取后续结果。已被替换掉的店不会被补回，符合条件的可用店铺不足时按实际数量显示。
- 调整家数后，抽选范围、结果摘要和底部列表数量同步更新；名单数量发生变化时抽选重新开始。调整失败时保留原名单、原家数和抽选结果，等待期间暂停替换和抽选。本次页面访问期间记住选择，重新搜索沿用，刷新页面恢复默认 20 家。
- 支持勾选一种或多种餐饮类型，多选按“任意一种”匹配；都不选或勾选“不限类型”表示全部。选项读取 Hot Pepper 官方分类目录并显示中文名称，筛选交给搜索服务处理。分类按主分类或副分类匹配，卡片展示主分类。
- 列表支持“替换这家”和“换一批餐馆”，沿用本次搜索的位置、范围和全部已选类型，按距离顺序读取后续结果。每次仍显示最多 20 家，不重复显示本次已换掉的店。剩余不足一批时只替换可用的数量，其他店铺保留；替换失败时原列表和抽选保留，可重试。
- 更改类型、范围或重新定位会清除旧列表并取消当前搜索；等待、空结果、搜索失败和超时均有提示。
- “帮我选一家”从当前列表的餐馆中随机选择，“换一家”在同一轮内不重复。全部选过后可以重新开始；重新搜索或成功替换列表会清除之前的抽选结果和计数。替换等待期间暂停抽选。
- 选中结果和餐馆列表均提供 Google 地图步行路线入口，以店铺坐标作为目的地。起点由地图处理，也可以在地图中调整。
- 搜索结果提供“调整条件／帮我决定／餐馆列表”快捷入口，随列表滚动保持可用；手机宽度调整页边距，地图与详情入口增大点击区域。
- 支持本机收藏。餐馆列表和抽选结果可收藏或取消收藏同一家店，状态保持一致，不改变名单或抽选轮次。标题下的“我的收藏”可展开查看，未定位、未搜索时也能打开店铺详情和导航。
- 收藏按店铺 ID 去重，较新的排在前面，保存当前店名、地址、类型、店铺坐标和安全的详情链接；不保存搜索中心、设备位置或 Key。刷新后仍保留，同源标签页之间会更新状态；无需登录，不跨设备同步，清除网站数据会移除收藏。收藏是保存时的信息，可通过店铺详情确认现状。
- 收藏读取与写入均检查数据；损坏数据、未知版本和存储权限错误会提示，写入失败不会显示为已收藏，原数据保留。首次加载只读取，不用空列表覆盖已有收藏。
- 餐馆服务的空坐标、布尔值或数组等异常值不会转换为 0 后进入列表、收藏或导航；坐标有效的数字和十进制字符串正常读取。异常搜索提示失败，可在相同条件下重试。地点与餐馆搜索失败时按钮显示明确的重试入口。
- 返回首页、店铺详情和重试按钮的点击区域至少 44 像素；在收藏列表取消某家后，焦点回到收藏入口，便于继续使用键盘。
- 320 像素预览下底部快捷入口保持单行；本地开发的 Next.js 角标已关闭，避免挡住“调整条件”。错误覆盖层和终端诊断仍可正常使用。

## 技术结构

使用 Next.js App Router、React、TypeScript 和 Supabase PostgreSQL。

浏览器调用本项目的 Next.js API，房间 API 验证成员身份后访问 Supabase，附近搜索 API 访问 Hot Pepper，地点检索 API 访问国土地理院地理院地図的地名搜索。Supabase Secret key 和 Hot Pepper API Key 只在服务端使用，地点检索无需新增 Key。

昵称用于显示；房间身份由浏览器中的 HttpOnly Cookie 验证。localStorage 保存部分界面状态，数据库保存共享清单和结果。不同浏览器会拥有不同的成员身份。

## 本地启动

所有命令均在 `what-to-eat` 项目根目录执行。

首次取得项目后安装依赖：

```sh
npm ci
```

在项目根目录的 `.env.local` 中配置以下变量的真实值：

- `SUPABASE_URL`：Supabase 项目的 HTTPS URL。
- `SUPABASE_SECRET_KEY`：同一项目的服务端 Secret key。
- `HOTPEPPER_API_KEY`：在 [Recruit WEB 服务](https://webservice.recruit.co.jp/register) 申请的餐馆搜索 Key。

两个 Key 变量均不要增加 `NEXT_PUBLIC_` 前缀，不要将真实密钥写进源码。环境文件已被 `.gitignore` 排除，重新取得项目时需要单独配置。

根目录 `.env.example` 仅列出变量名，值均为空，可用于核对配置；真实值仍保存在 `.env.local`，不要覆盖已有配置。

如果使用全新数据库，按照文件编号在 Supabase SQL Editor 中执行 `app/database/001_initial_schema.sql` 至 `007_draw_room.sql`。已完成配置的数据库无需为了启动而再次执行全部 SQL。

启动开发服务器：

```sh
npm run dev
```

打开终端显示的 Local 地址，通常为 `http://localhost:3000`。终端需持续运行；按 Control + C 会停止本地网页服务。

开发环境可通过 `/api/health/database` 检查连接，该接口在生产环境返回 404。

打开 `/nearby` 使用附近搜索。设备定位需要浏览器及系统的位置权限；本机 `localhost` 可用于开发验证，手机上的设备定位需要 HTTPS。手动指定可直接输入地点并选择候选，建议使用日文名（例如 `新宿駅`），每次最多显示 10 个候选。开发环境的 `/api/health/hotpepper` 只检查 Key 是否已配置，实际搜索才能验证其有效性。地点选择、餐馆列表与当前抽选轮次保存在页面状态中，刷新后需重新选择搜索中心并查找。

地点检索只在提交时请求服务，不做逐字自动补全；上游地点响应缓存一天。国土地理院对该搜索服务的[官方说明](https://github.com/gsi-cyberjapan/gsimaps/issues/29)指出，接口和长期提供情况可能变化，公开上线前应复核可用性；服务接入隔离在 `/api/locations`，便于替换。页面已标注地点数据来源。

分类在进入页面和手动重试时读取；带类型的餐馆搜索会在服务端重新检查所有分类是否仍可用。分类请求不缓存失败结果；目录无法读取时可以重试，也可以按不限类型搜索。多个分类合并为一次搜索请求并去重，不接受目录之外的代码，也不会在其中一个类型失效后自动放宽条件。分类、分页和匹配规则见 [Hot Pepper 官方接口说明](https://webservice.recruit.co.jp/doc/hotpepper/reference.html)。无需新增 Key 或安装依赖。

## 检查与测试

检查代码规范和构建：

```sh
npm run lint
npm run build
```

自动流程测试需要开发服务器已在 `http://localhost:3000` 运行。在另一个终端执行：

```sh
node scripts/test-group-flow.cjs
```

测试会创建独立测试房间和两名成员，检查抽选权限、空清单、共享结果，以及修改候选后旧结果失效。结束时测试房间保留两名成员和三条抽选历史，候选清单为空。脚本只在内存中保存测试 Cookie。

这个脚本测试 API 和数据库流程；页面按钮和同步显示还需要在普通窗口与无痕窗口中分别验收。

附近餐馆与地点的数据检查、去重、详情链接、直线距离、抽选规则、导航链接，以及地点和分类接口、多选类型、分页、单家与整批替换规则及错误处理可单独测试，无需启动服务或调用外部接口：

```sh
node scripts/test-nearby.cjs
```

浏览器手动验收：先定位，再选择范围并查找；检查餐馆列表及数量；更改范围后旧列表应清除，再次查找显示新结果。没有收录餐馆时应显示空结果提示，搜索失败后可重试。页面展示 [Hot Pepper 要求的来源署名](https://webservice.recruit.co.jp/doc/hotpepper/guideline.html)。

找到餐馆后，点击“帮我选一家”和“换一家”，同一轮内店铺不应重复；全部选过后“换一家”应禁用并提示重新开始。重新开始、重新搜索（包括相同条件）、更改范围和重新定位后，应开启新一轮。点击“就吃这家，去导航”，应在 Google 地图中打开目的地对应的步行路线。链接遵循 [Google Maps URLs](https://developers.google.com/maps/documentation/urls/guide) 格式，使用者可在地图中确认起点、终点与实际路线。

手动方式验收：不授予设备位置权限，选择“手动指定”，输入 `新宿駅` 并检索，从候选选择搜索中心，再查找餐馆、抽选和导航。尝试完整日本地址及无结果的输入；更改输入或切换回当前位置时，旧地点、餐馆与抽选应清除。定位等待期间切换至手动方式，后续设备定位结果不应覆盖手选地点。

页面与手机验收：当前位置和手选候选均不得展示经纬度或定位精度。选中手动地点后输入与候选列表收起，只保留地点名称和更换入口；“更换地点”展开后不更改输入，直接收起，已有列表和抽选应保留。搜索后测试三个快捷入口，长列表中应能快速返回抽选或调整条件；跳转目标不应被快捷入口遮住。仍需在真实手机上检查按钮、文字换行和地图应用跳转。

类型筛选验收：只勾选“拉面”并搜索，再加选“和食”重新搜索，摘要应显示已选类型，结果匹配其中任意一种。更改勾选时旧列表和抽选应立即清除，地点和范围保留。取消全部勾选或选择“不限类型”可恢复全部类型搜索。没有匹配店铺时，页面应提示改类型或扩大范围。

替换验收：先抽选一次，再点击某张卡片的“替换这家”，确认仅该位置换成另一家、列表数量保持且抽选回到新一轮。再次替换或点击“换一批餐馆”，店铺不得与当前列表或本次换掉的店重复。剩余不足 20 家时只替换剩余数量，耗尽后按钮禁用并提示调整条件。替换中的按钮和抽选按钮应暂时禁用，失败后原列表仍可使用；更改范围、类型或地点后，未完成的旧替换不得写回新列表。检查替换后店铺的导航目的地与详情链接同步更新。

显示家数验收：首次搜索默认选择 20 家，依次切换 5、10、15、20 家，检查列表数量、抽选说明和底部快捷入口一致。减少再增加应恢复之前收起的店铺；5 家时替换单家或换一批，再增加家数，不能补回被换掉的店。储备不足时检查后续补齐和请求失败后保留原列表；餐馆总数不足选择的家数时显示实际数量。重新搜索应沿用选择，刷新后恢复 20 家。

收藏验收：搜索后收藏一家店，列表与抽选结果中同一家店的按钮应同步为已收藏，抽选计数不变。展开标题下的“我的收藏”，检查店名、地址、导航和详情链接。刷新后无需重新定位、搜索即可查看收藏；换一批或调整类型不应移除收藏。再次点击已收藏可取消，同源的另一标签页应同步更新；存储不可用时应明确提示。

收尾验收：在 320 和 375 像素窄屏检查类型与家数按钮、长店名、详情和导航入口、收藏列表和底部快捷栏。网络或上游数据异常后，地点和餐馆搜索按钮应显示重试文字，重试仍使用选定地点及筛选条件。上游无效坐标的拒绝和恢复由 `test-nearby.cjs` 使用模拟响应验证，不依赖外部服务制造故障；实际手机的位置权限、软键盘和地图应用仍需真机验收。

## 主要目录

- `app/group/`：多人房间页面、加入表单、云端候选与抽选界面。
- `app/nearby/`：地点、范围和多选类型、可替换的餐馆列表、抽选界面，以及数据检查、距离计算和导航链接；`restaurant-list.ts` 管理去重和替换规则。
- `app/nearby/favorites.ts`：本机收藏的数据验证、去重、安全字段和保存规则；`useRestaurantFavorites.ts` 连接浏览器存储和页面状态。
- `app/api/locations/`：检索日本地点，验证、排序和去重候选点位。
- `app/api/nearby/`：验证位置、范围、类型和分页起点，访问餐馆搜索服务；`genres/` 提供官方分类目录。
- `lib/hotpepper/genres.ts`：仅在服务端使用 Key 读取和检查分类目录。
- `app/api/rooms/`：创建、加入、读取房间，以及候选增删、清空和抽选 API。
- `lib/rooms/access.ts`：验证房间成员身份。
- `lib/supabase/admin.ts`：服务端数据库客户端。
- `app/database/`：数据库结构和函数 SQL。
- `scripts/test-group-flow.cjs`：多人 API 流程测试。
- `scripts/test-nearby.cjs`：附近餐馆与地点数据、距离、抽选规则、导航链接和地点接口测试。

## 本地生产模式

先停止占用同一端口的开发服务器，再执行：

```sh
npm run build
npm run start
```

构建只生成运行文件；`npm run start` 才会持续提供网页服务。该项目包含服务端 API，上线时需要能够运行 Next.js 服务端的环境。
